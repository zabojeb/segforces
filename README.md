# SegForces

Локальный «Codeforces» для курса «Основы программирования на C и Linux». Открываешь свой репозиторий `Practice-Имя.Фамилия` и получаешь:

- список задач с баллами, дедлайнами и статусами;
- редактор с подсказками;
- прогон тестов и сдачу грейдеру в одну кнопку;
- лидерборд курса;
- помощь Claude прямо в задаче.

## Установка

Нужен только Python 3.8+ (на macOS и Linux он уже есть). Ставить пакеты не нужно.

1. Положи папку `segforces` куда удобно, например рядом с репозиторием курса.
2. Запусти:

   ```bash
   python3 segforces/server.py --open
   ```

   На macOS можно просто дважды кликнуть `SegForces.command`.
3. SegForces сам найдёт репозиторий `Practice-*`. Если не найдёт, откроется экран выбора папки, и выбор запомнится.

Windows — через WSL (Ubuntu), как и весь курс. Интерфейс использует редактор и подсветку с CDN, поэтому нужен интернет.

## Что умеет

- **Задачи.** Все сессии из `grading.yml`: баллы, дедлайны, статус («принято», «не принято», «готово к сдаче»), ранг как на Codeforces, график активности.
- **Редактор** (Monaco, как в VS Code) с автосохранением прямо в файлы репозитория.
  - В bash подсвечивает типичные ошибки: нет shebang, пробелы вокруг `=`, `[[`/`]]` без пробелов, `read -p`, `{1..$n}`, CRLF.
  - В Makefile ловит пробелы вместо TAB.
  - `⌘.` / `Ctrl+.` — быстрое исправление.
- **▶ Запустить** (`⌘↵`) гоняет `run_test.sh` задачи и показывает вердикт: Accepted / Wrong answer on test N / Runtime error / Compilation error.
  - Под вердиктом подсказки, что чинить, с кнопками «добавить shebang», «chmod +x», «запустить Docker».
  - В C-задачах тесты прячут вывод компилятора, поэтому при падении SegForces сам пересобирает решение той же командой (`make -f Makefile.Student …`) и подсвечивает ошибки gcc в редакторе.
- **Консоль.** Любая команда (`./factorial.sh 5`) в копии папки задачи: в Docker (Linux, как у тестов) или локально. Показывает stdout/stderr и какие файлы скрипт создал или поменял.
- **Отправить** (`⌘⇧↵`): коммит с сообщением ровно `GRADER\n<SessionXX/задача>` (как `make submit`) и push в `master`. После отправки окно ждёт результат грейдера из GitHub Actions, включая скрытые тесты.
- **Лидерборд** — публичная таблица курса:
  - место, процент, задачи и прогресс по сессиям у каждого;
  - найди себя и нажми «Это я»;
  - баллы из таблицы засчитывают задачи как решённые, даже если `gh` не настроен.
  - у каждой задачи видно, сколько человек её решило (`👤 ×29` в списке, «Решили 29 из 32» на странице задачи) — по той же таблице.
- **✦ Claude** (`⌘J`) — чат по задаче. Claude видит условие, твой код и вывод тестов.
  - Режим «Подсказки» наводит на мысль без готового решения, «Полный разбор» объясняет решение целиком.
  - Claude отвечает строго по условию из ReadMe и открытым тестам: не придумывает требований и тест-кейсов, которых там нет, и ссылается на условие.
  - Claude только читает файлы, меняешь их ты сам.
- **Проекты** (например, Huffman archiver) — отдельный блок «Проект» в списке задач, хотя проект живёт в своём git-репозитории. Редактор, консоль и чат работают как в задачах, но:
  - ▶ запускает `make test` в корне проекта;
  - «Отправить» делает обычный коммит со своим сообщением и push в текущую ветку репозитория проекта (без `GRADER` и грейдера); бинарники и артефакты сборки не отмечаются;
  - баллы проекта не входят в общий счёт и ранг.

  Проект подключается в `config.json` (см. «Где что хранится»):

  ```json
  "projects": [{"name": "huffman", "path": "~/HuffmanProject", "points": 100, "deadline": "2026-11-16"}]
  ```

## Что поставить

| Что | Зачем | macOS | Linux (Ubuntu) |
|---|---|---|---|
| Docker | тесты почти всех задач | Docker Desktop | Docker Engine + `sudo usermod -aG docker $USER` |
| `gh` | результаты грейдера | `brew install gh` | `sudo apt install gh` |
| `claude` | чат с Claude (необязательно) | `npm install -g @anthropic-ai/claude-code` | то же |
| `shellcheck` | больше подсказок в bash (необязательно) | `brew install shellcheck` | `sudo apt install shellcheck` |

После установки один раз выполни `gh auth login`, а для чата — `claude`, затем `/login` (нужна подписка Claude или API-ключ). Без `claude` в чате работает кнопка «📋 Промпт»: она собирает условие, твой код и вывод тестов в один текст, который можно вставить в Claude вручную.

Состояние всего этого видно по точкам в правом верхнем углу. Клик по ним открывает подсказки, как починить.

## Как сдаётся задача и почему это безопасно

- В коммит попадают **только отмеченные файлы одной задачи**. Сервер сверяет каждый путь со свежим `git status` этой задачи, поэтому `open_tests/`, `.hidden_tests/`, `ReadMe.md`, `run_test.sh` и файлы других задач туда не попадут, даже если подделать запрос.
- Сообщение коммита всегда ровно `GRADER\n<задача>`, без подписей и соавторов. Git-хуки при этом отключены.
- Перед отправкой видно список файлов и сообщение. Ничего не уходит без нажатия «Отправить».
- Если файл не сохранился, SegForces не даст запустить тесты или отправить старую версию.
- Сервер слушает только `127.0.0.1` и отвечает лишь странице, которую сам отдал (одноразовый токен), так что другие сайты в браузере управлять им не могут.

## Где что хранится

| | macOS | Linux |
|---|---|---|
| настройки | `~/Library/Application Support/SegForces/config.json` | `~/.config/segforces/config.json` |
| история прогонов, посылок, чатов | `~/Library/Application Support/SegForces/<репозиторий>/` | `~/.local/share/segforces/<репозиторий>/` |

В репозиторий курса SegForces ничего своего не кладёт. Переменная `SEGFORCES_HOME=/папка` переносит и настройки, и данные в одно место.

## Параметры запуска

```
python3 segforces/server.py [--repo ПУТЬ] [--port 7331] [--open]
```

- `--repo` — путь к `Practice-*` (иначе ищет сам или берёт выбранный ранее).
- `--port` — порт; если занят, берётся следующий свободный.
- `--open` — открыть браузер.

## Если что-то не работает

- **Docker «не отвечает».** Docker Desktop завис: так бывает после сна ноутбука. Нажми «Перезапустить» в плашке; на Linux выполни `sudo systemctl restart docker`.
- **Чат молчит или ругается на логин.** Проверь `claude auth status` в терминале, при необходимости выполни `claude` → `/login`.
- **Не видно результатов грейдера.** Нужен `gh auth login`. Лидерборд при этом работает и без него.
- **Не нашёл репозиторий.** Укажи путь на экране выбора или запусти с `--repo ~/путь/к/Practice-Имя.Фамилия`.
- **Порт занят.** Сервер сам возьмёт следующий, адрес напишет в терминале.
